## 新たなブロッキング発見 (ラチェット基準：実証された欠陥)

**B1 (prereg §2 較正 — A2 ゲート実行における実行不可能な制約)。** リプレイ選択制約は「replay 上で codex・qwen の発火率 0 かつ necessity-false-fire の harmful 率 ≤ 10%」と読まれるが、§1 に従うと、harmful は `cost_ratio = tokens(sentinel run)/geomean(bare)` を必要とする。つまり、実際に介入された sentinel の実行が必要であり、リプレイコーパスは非介入の bare/shadow シリーズ（「非介入腕のシリーズに限り妥当」）のみである。候補 (T_abs,w) ごとの harmful レートは定義されていないため、凍結されたルールはそのままでは機械的に実行可能ではない。ライターは、タイミングメトリクスへの目標の変更（「発火した run に分解が入った場合の推定ではなく」）についても、まさにこの計算可能性の理由から正しく行っているが、制約側には同じ修正が適用されていない。この制約は重要であることに注意されたい — (T_abs, 40%) は、sonnet の定常状態 ~56% において、ほぼすべての sonnet L-band ターンで発火するため、DB から除外される必要があり、その操作的な意味は凍結されていなければならない。修正（1行）：「necessity-false-fire 率 ≤ 10%（replay 上）」とする。harmful/harmless の層別化はライブ A1 分析時に別途報告する。または、リプレイで計算可能な明示的な害のプロキシを定義する。この修正では、(40k, 40%) を除外できるという意図された両側性は維持される。

**B2 (DESIGN §4 — 凍結された述語におけるターン2〜3の slope の矛盾)。** 述語ブロック（「これが唯一の定義・全変数を凍結」）は `t−K 未取得なら slope 未定義=発火しない` (K=3 → 定義された最も早い slope はターン4) と書かれているが、縮退規則の項目は「傾きはターン2から」と書かれている。これら2つの句は、ターン2〜3に対して異なる動作（部分 K の slope vs ゲートされた slope）をもたらすため、実装者はどちらかを選ぶことになり、凍結は失敗する。マテリアルな影響は低い（ターンはレベルレッグが支配する）が、これは明示的に凍結された変数のリストにある。修正（1行）：「傾きは MA_{t−3} 取得後（t≥4）から」に修正する。または、部分 K の退化を明示的に定義する。

## 非ブロッキングな発見

- **NB1 (A1 エッジ):** 分割された bare シード（1つのシードで window_error が発生し、もう1つはクリーン）を伴う (model,task) セルにおいて、必要性の反実仮想は未定義である（ bare セル内の any-seed か all-seed か）。現在の読みである「対照 bare に window_error 無し」= all-clean（strict）が自然的な読みであり、これを1語で明確化すべきである。
- **NB2:** 「bare/shadow turn 系列 48本」— bare + always-harness における非介入アームは、48のうちの32（3アームグリッド）である。カウントを修正するか、sentinel の発火前セグメントの除外を明記する。B1の修正段落に統合可能。
- **NB3 (リプレイ目標):** 分母（すべての sonnet bare/shadow 実行に対する「run の割合」、未発火は帯域外）と「fire 時点」= 初回発火を明示する。すべての実行に対する読みは自然であり、より厳しいものである。
- **NB4:** codex の `トークン比 ≤ 1.05` は §4 テーブルでは confirmatory であるが、統合ルールには存在しないため、違反時の処理が未定義である（qwen 行が行っているように、差し戻しまたは中立を明記する）。
- **NB5:** §2 カットメニューの「閾値 0.6→0.8 に再設定」は、v0.2 §4 で定義されたどの閾値にも対応していない（confirmatory `<1.0` / effort `<0.8`）。p2-L カットオプションが決裁で選択された場合に解決されるべき数値の不一致。フルプランの GO パスは影響を受けない。
- **NB6:** DESIGN §3 のターンイベントスキーマは、`run_meta/arm/seed` を搭載していない（ライターの主張では「すべてのイベントにおいて」であり、r2 の採択リストでは ターンシリーズ が含まれていた）。`task_id` → 実行レコードの結合が実行可能なフォールバックであるが、オプションのフィールドを1つ追加するか、結合に関する1文を追加してほしい。
