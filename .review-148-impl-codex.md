## Findings (incremental; blocking status finalized below)

### 1. CRITICAL — whitespace-only citations become universally valid and can fabricate a promoted K=2 theme

**Lens:** (c) silent narrowing / normalizer boundary; (d) trust inversion; (b) malformed/vacuous output.

**Evidence:** `scripts/raw-review.sh:526` rejects only a pre-normalization empty quote. `scripts/raw-review.sh:546-553` then normalizes the quote and accepts a source line when `normalized_source` begins with it, without rejecting an empty normalized value. The pinned normalizer at `scripts/lib-state-fold.sh:124-153` folds a spaces-only value to the empty string. I ran a reviewer that cited two real filenames from different weeks but supplied only one space after each colon, invented `THEME: fabricated recurrence`, and requested `PROMOTE: yes`. Reproduction output:

```text
rc=0 ... blocks=1 fabricated=0 rejected=0 candidates=1 ... error=none
candidate_promote=yes candidate_run_k=2 member_hashes=2
```

No lesson text was cited. Both blank citations hashed to the same empty-string hash; the host nevertheless derived K=2 from the filenames and emitted a promoted candidate. This bypasses the mechanism that is supposed to make model output evidence-authentic.

**Failure scenario:** a malformed, compromised, or prompt-injected reviewer names any two in-window files, uses whitespace-only member prefixes, and obtains a host-validated cross-week promotion for arbitrary theme/evidence text.

**Flip condition:** after normalization, reject an empty citation key before matching or hashing; add a regression test proving spaces/tabs/NFKC-space-only member prefixes are rejected into the named rejects artifact and cannot produce `promote: yes` or `candidates>0`.

### 2. MAJOR — second-resolution watermark permanently misses an equal-second late arrival

**Lens:** (a) never-fires; (e) durability.

**Evidence:** `scripts/raw-review.sh:313` selects late files only when `late_mtime > watermark`; `scripts/raw-review.sh:784-786` stores the run-start epoch at whole-second resolution. I completed a successful nightly run, created an old-week file that had not been in its prompt, set that file's mtime to exactly the stored success watermark second, and ran another successful nightly review. Reproduction output:

```text
first_rc=0 second_rc=0 stored_watermark=1787665019 late_mtime=1787665019 second_prompt_occurrences=0
```

Because the file's date is outside W∪W−1 and its mtime equals (rather than exceeds) the seconds-granularity boundary, it is absent from the next prompt and the next success advances the watermark past it. The frozen design's arbitrarily-late/self-healing guarantee is therefore false at the timestamp boundary.

**Flip condition:** make the late-arrival boundary lossless (for example, persist sufficient sub-second precision or include the equality boundary with durable de-duplication), and add a regression fixture where a post-snapshot old-week file has mtime equal to the stored watermark and appears in the next prompt exactly as specified.

### 3. MAJOR — the macOS timeout fallback leaves the reviewer process tree running after fail-closed exit

**Lens:** (b) timeout failure; (f) external egress boundary.

**Evidence:** this Darwin host has neither `timeout` nor `gtimeout`, so `scripts/raw-review.sh:401-420` is the active path. It kills only `model_pid`, not a process group. I configured a sole reviewer whose direct shell spawned a TERM/HUP-resistant descendant and then slept. With `reviewer_timeout_s=1`, raw-review notified and exited 1, but the descendant continued and wrote its sentinel afterward:

```text
timeout_rc=1 receipt_error=chain-exhausted descendant_survived=yes
```

Real reviewer CLIs commonly launch child runtimes; this permits the actual external-model process to outlive the per-entry timeout and the failure receipt/notification, and potentially overlap a fallback call.

**Flip condition:** run each reviewer in a dedicated process group and terminate/reap the group on timeout (the repository's bounded-process machinery already demonstrates this behavior), with a macOS/no-`timeout` regression proving a grandchild cannot survive.

### 4. MAJOR — `install.sh --check` tokenizes an indented config as wired while production rejects it

**Lens:** (b) `--check` row parity / never-fires observability.

**Evidence:** `install.sh:819-824` accepts leading whitespace before both `producer=` and `reviewer`; `scripts/raw-review.sh:221-242` accepts neither and marks such lines invalid. With both lines indented by two spaces, the health check emitted no `review-config` warning, while the real command exited configuration-class 2:

```text
check_rc=0 review_config_warnings=0 raw_review_rc=2 ... error=config
```

This makes the wired/config row disagree with the executable parser on the exact configuration it is supposed to diagnose.

**Flip condition:** share or exactly mirror the production token grammar in `check_raw_review`, and add paired tests showing every accepted check tokenization is runnable while indented/otherwise-invalid lines produce literal `warning: review-config`.
